## Résumé

La révision de versions répond à un certain nombre de questions
classiques du développement logiciel:

- Comment conserver un historique de toutes les étapes de
    développement?
- Comment comparer facilement deux fichiers à des étapes différentes?
- Comment travailler en commun sur un projet complexe?
- Comment tester des pistes sans prendre le risque de tout casser?
- Comment proposer des modifications à un projet auquel on ne
    participe pas avant?

Même si les documents diffèrent fortement entre code informatique et
travaux de sciences humaines, les grandes questions restent identiques.

Comment utiliser Git, un logiciel de référence dans le développement
informatique, dans un contexte de science humaines, théologie, DH, ou ce
que vous voulez?

## Organisation du projet

L’idée de cette documentation est de proposer une autre démarche que
les excellentes ressources qui existent.
Nous proposons donc un plan un
peu particulier:

- Dans une première partie XXX, nous parcourons les possibilités de l’outil sous forme
    narrative: pas de code, pas de logiciel à installer.
L’idée est de
    comprendre les possibles avant de passer à la pratique et
    d’acquérir un minimum de vocabulaire.
- Dans une deuxième partie XXX, nous passons au travail à proprement parler.
    L’enseignement est beaucoup plus rude, mais conçu pour permettre un
    apprentissage rapide et efficace.
- Dans une troisième partie, nous discutons des enjeux et des
    difficultés d’un passage réel à git.

Découvrez le logiciel de gestion de révision *dont vous êtes le héros*
